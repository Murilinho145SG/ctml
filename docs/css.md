# CTML CSS

CTML uses regular `.css` files. One or more stylesheets can be declared in the CTML header and are parsed during the Rust build in header order. Their rules enter the cascade in that same order, so later sheets take precedence when layer, importance, and specificity are equal. The compiled application receives native style data, so it does not include a CSS parser or browser runtime.

```ctml
<headers>
    <application name="Example" desktop />
    <stylesheet href="reset.css" />
    <stylesheet href="main.css" />
</headers>

<body>
    <main>
        <h1 class="title">Hello, CTML</h1>
        <p id="intro">A native page styled with CSS.</p>
    </main>
</body>
```

Each stylesheet path is relative to the Rust application's `src/` directory.

All declared and imported stylesheets match against the same CTML selector tree. CTML does not currently define component boundaries, shadow trees, or scoped-style sources, so selectors have document-wide scope and component encapsulation is deferred until such boundaries exist.

Stylesheets can import local files with a quoted path or `url()`, for example `@import "shared/colors.css";`. Imported rules are expanded where the import appears, and nested imports resolve relative to their importing file. Imports cannot escape the application's `src/` directory or form cycles. Network URLs, import media qualifiers, and escaped import paths are currently rejected. Imported files are tracked as build dependencies so Cargo recompiles the application when they change.

The CSS crate also exposes a local resource loader for binary resources. It resolves URL paths relative to their stylesheet, rejects external schemes, queries, fragments, and paths that escape the configured root, and caps reads at 64 MiB. `@font-face` accepts ordered `local()` and local `url()` sources, with `format()` and `tech()` hints; it tries candidates in order and registers the first available font under the declared `font-family`. URL files are embedded in the application build. Static `font-weight`, `font-style`, and `font-stretch` descriptors are supported, along with variable `font-weight` ranges and oblique angle ranges. Variable `font-width` ranges are not supported.

Stylesheet files must be UTF-8. An optional UTF-8 BOM is removed. CSS comments are discarded outside quoted strings, and an unterminated comment is an error. The legacy `@charset` rule does not change decoding and is unsupported.

## CSS value processing

CTML follows these value-processing stages for the properties it supports:

- **Specified values:** the stylesheet parser retains declaration values as CSS token text after removing comments and handling escapes. Property-specific parsers validate the supported grammar; invalid or unsupported declarations do not become style values.
- **Computed styles:** the cascade combines inherited text properties, modeled initial values, stylesheet rules, and inline declarations using importance, layer order, specificity, and source order. Custom properties and supported `var()` and `attr()` substitutions are resolved before the receiving property is parsed. The renderer stores the resulting values in its internal text style; it does not expose a CSSOM.
- **Used values:** relative lengths and percentages resolve when their needed context is available, including font metrics, line height, viewport dimensions, containing text area, or the active page size. Layout then calculates text flow, wrapping, and line metrics. Resizing recompiles styles with the new viewport dimensions.
- **Actual values:** the native shaping and rasterization path selects available font faces, positions glyphs, maps colors to the display's sRGB output, and paints the resulting pixels into the render target. Pixel placement and glyph metrics therefore reflect the native font and raster backends.

These stages describe CTML's implementation boundary rather than a promise that every CSS property or every CSS value grammar is supported.

Named `@layer` order statements and blocks are supported, including escaped identifiers, nested named layers, and anonymous blocks. Anonymous layers remain distinct across stylesheet imports. Normal declarations in later layers outrank earlier layers, while `!important` layer order is reversed; unlayered normal rules outrank layered normal rules, and layered important rules outrank unlayered important rules.

Malformed layer declarations and unterminated comments report the source file, line, and column during the build. Incomplete rules at end of file, malformed selector rules, and unsupported at-rules are discarded so later rules can still apply. Invalid declarations are skipped so later declarations in the same rule can still apply.

```css
body {
    font-family: sans-serif;
    color: #222222;
    background-color: white;
}

main .title {
    color: #2563eb;
    font-size: 32px;
    font-weight: 700;
    line-height: 1.2;
    letter-spacing: 0.02em;
    text-transform: uppercase;
}

#intro {
    font-size: 1em;
    font-style: italic;
    text-decoration: underline;
}
```

## Supported CSS subset

- Selectors: type, class, ID, compound, descendant, direct child (`>`), adjacent sibling (`+`), general sibling (`~`), comma-separated groups, `*`, CSS escaped identifiers, `:is()`, `:where()`, `:not()`, relational `:has()` with descendant, child, adjacent-sibling, and general-sibling relative selectors, inherited `:lang()`, `:dir(ltr|rtl)`, `:link` and `:any-link` for `<a href>`, `:hover`, `:active`, `:focus`, `:focus-within`, and keyboard-driven `:focus-visible`, and attribute selectors for presence, exact match, token (`~=`), language prefix (`|=`), prefix (`^=`), suffix (`$=`), substring (`*=`), and ASCII-insensitive (`i`) or sensitive (`s`) matching.
- Structural pseudo-classes: `:root`, `:empty`, `:first-child`, `:last-child`, `:only-child`, `:nth-child()`, `:nth-last-child()`, and the corresponding `-of-type` forms. `:nth-*` accepts integers, `odd`, `even`, An+B expressions, and `of S` selector lists on `:nth-child()` and `:nth-last-child()`.
- `display: flex | inline-flex` establishes row, reversed-row, column, or reversed-column flow for direct child items. Reverse directions reverse the visual sequence of order-modified items while retaining source selector positions. The `order` property sorts those items visually, with equal values retaining source order before direction reversal. Block row flex supports `justify-content: flex-start | start | center | flex-end | end | space-between | space-around` to align items along the main axis; `space-between` distributes free row space between direct items, while `space-around` gives each item equal surrounding space. `flex-start` and `flex-end` follow the reversed main axis, while `start` and `end` follow the writing direction. Column flex supports `align-items: flex-start | start | center | flex-end | end` to align item lines on the cross axis, and direct items support the same values plus `align-self: auto`; stretch and baseline alignment are not modeled. `gap`, `row-gap`, and `column-gap` accept `normal`, non-negative font-relative lengths and percentages, and supported `calc()` expressions. Row flex uses `column-gap`; column flex uses `row-gap`. Percentage gaps resolve when the main-axis size comes from the viewport or an explicit fixed length; they resolve to zero when that size is indefinite. Item sizing, wrapping, row cross-axis alignment, `space-evenly`, and wrapped cross-axis gaps are not implemented.
- `width`, `min-width`, and `max-width` on the page `body` and block elements constrain text flow. `inline-size`, `min-inline-size`, and `max-inline-size` size the inline axis in horizontal and page-root vertical writing modes. Supported values include non-negative lengths and percentages of the containing text area, plus `min-content`, `max-content`, and `fit-content(<length-percentage>)` measured from the element's text. `width`/`inline-size` also accept `auto`, min-size properties accept `auto`, and max-size properties accept `none`. Nested inline-size percentages resolve against the nearest containing text area; nested content-block `height`, `block-size`, `min-height`, `min-block-size`, `max-height`, and `max-block-size` percentages resolve against an explicitly sized ancestor's used block extent.
- Empty blocks reserve flow space through `height`, `min-height`, and `max-height`; nested `height` and `block-size` percentages resolve against an explicitly sized ancestor. Content-bearing blocks use fixed `height`/`block-size` and min/max constraints for following flow; auto height starts from content height, then maximums cap the used block extent. Text that exceeds a fixed or maximum block size remains visible under the default `overflow: visible`, and following blocks start after the sized block extent. The one- and two-value `overflow: visible | hidden | clip | auto | scroll` forms and the `overflow-x`/`overflow-y` longhands clip descendant text, fragment backgrounds, selections, and decorations to the used inline and block extents of content-bearing blocks in horizontal and page-root vertical writing modes. Clipped text does not receive pointer or selection hits. On the page root, `auto` and `scroll` accept mouse-wheel input along scrollable axes. `scroll` draws a scrollbar on the selected root axis; `auto` draws one when formatted content overflows. Thumb size and position follow the formatted root content and scroll offset. `hidden` and `clip` do not respond to user scrolling. Content-bearing blocks with `overflow-x` or `overflow-y: auto | scroll` scroll under the pointer and draw a scrollbar on each overflowing or forced axis under horizontal and vertical page roots; descendant text, backgrounds, selections, decorations, and hit testing follow the nested offsets. Under a horizontal page root, wheel deltas chain from inner scrollers to scrollable ancestors and then to the page root when an inner scroller reaches its boundary. Overflow clipping supports nested orthogonal blocks under both horizontal and vertical page roots, including their descendant paints and pointer/selection hits. Nested orthogonal text flow and orientation remain constrained by the page root. `block-size`, `min-block-size`, and `max-block-size` size the block axis in horizontal and page-root vertical writing modes. These sizes accept non-negative lengths and percentages; nested content-bearing block percentages resolve against an explicitly sized ancestor's used block extent.
- Under a horizontal page root, nested vertical blocks wrap against their own inline extent, compose glyph columns, fragment backgrounds, selection highlights, and decorations locally, apply overflow clipping in their transformed bounds, and map pointer hits back to the buffer. Cross-axis block sizing still constrains page flow. Nested orthogonal blocks under a vertical page root are not composed independently yet.
- `box-sizing` accepts `content-box` (the initial value) and `border-box`. Physical and logical border shorthands and side longhands support `thin`, `medium`, `thick`, non-negative font-relative lengths, standard border styles, CSS colors, and `currentColor`. On nested content-bearing blocks, widths affect used inline and block dimensions when the corresponding style is not `none`; `border-box` includes those widths with supported padding, and border edges paint around the block. `border-radius` supports one-to-four values, optional elliptical radii separated by `/`, and physical corner longhands with non-negative lengths and percentages. Rounded border edges are painted on nested content-bearing blocks. `outline` and its width, style, color, and offset properties paint independent dashed, dotted, solid, double, and shaded outlines around nested content-bearing blocks; signed font-relative offsets and rounded corners are supported. Positive numeric `aspect-ratio` values size the auto dimension from a definite or stretched dimension on horizontal blocks, including empty blocks. Explicit dimensions and min/max constraints still apply, and content taller than the preferred ratio size can increase the block. Vertical writing modes and ratio syntax combining `auto` with a ratio are not supported yet. `box-shadow` supports multiple comma-separated outer and inset shadows with signed offsets and spread, non-negative blur lengths, CSS colors and `currentColor`, and rounded corners on content-bearing blocks. `border-image-source` accepts embedded PNG/JPEG `data:` URLs, `border-image-slice` accepts one-to-four non-negative numbers or percentages with optional `fill`, `border-image-repeat` accepts one or two `stretch`, `repeat`, `round`, or `space` values, `border-image-width` accepts one-to-four `auto`, number multipliers, non-negative lengths, or percentages, and `border-image-outset` accepts one-to-four number multipliers or non-negative lengths. The `border-image` shorthand expands source, slice, width, outset, and repeat values in source order; its source must use the implemented `data:` image form. The nine source regions paint with the computed image widths and selected edge or center tiling mode; `auto` uses the source slice width. Other source types and rounded border-image corners are not implemented. Logical border sides follow the computed `writing-mode` and `direction`, and physical and logical declarations follow source order. Root body borders and border images paint around the page viewport with supported rounded corners.
- Inline text boxes also paint embedded PNG/JPEG `border-image` sources around each formatted fragment, using the supported slice, repeat, width, and outset values.
- `box-decoration-break: slice | clone` is supported for physical border sides on the inline element's own text fragments in horizontal writing mode. `slice` draws top/bottom borders on each fragment and left/right borders at the outer inline start/end; `clone` repeats all four sides on every fragment. Inline padding, radius, shadows, decoration across descendant text, and vertical writing mode are not included in this support yet.
- Physical `margin` and side longhands, plus logical `margin-inline`/`margin-block` and their start/end longhands, accept signed font-relative lengths and percentages of the containing block's inline size. They offset text and add to or subtract from block flow. Logical sides follow `writing-mode` and `direction`; declarations follow source order. `auto` margins currently resolve to zero.
- `visibility: visible|hidden|collapse` inherits. Hidden text keeps its layout space but does not paint text, fragment backgrounds, selection highlights, or decorations; `visibility: visible` can restore rendering on a descendant. `collapse` behaves like `hidden` because table formatting is not implemented.
- `content-visibility: visible|hidden|auto` accepts these values. `hidden` skips descendant text and generated content, suppresses descendant painting and hit testing, and applies size, style, layout, and paint containment; explicit sizes remain in effect, and auto-sized content reserves zero block flow height unless `contain-intrinsic-size` provides a fallback. `auto` applies style, layout, and paint containment and skips content outside a viewport margin of 50%; skipped boxes use size containment and `contain-intrinsic-size` fallbacks, while focused and selected content remains available. Style containment scopes counter and quote changes to the element subtree. `contain: style`, `content`, and `strict` provide style containment; `layout`, `content`, and `strict` set layout-containment state, but their containing-block, formatting-context, and stacking effects await positioned and float layout. `paint`, `content`, and `strict` clip descendant painting to the block box. `contain: size` and `strict` remove intrinsic block flow height and horizontal intrinsic width contributions for content-bearing blocks while allowing visible text overflow; explicit sizes remain in effect. `contain: inline-size` removes the contained inline contribution, including when an orthogonal writing mode maps it to the page block axis; empty orthogonal boxes use the corresponding physical intrinsic fallback. `contain-intrinsic-size` and its width/height longhands accept non-negative lengths, `none`, and `auto` fallback pairs; fallback physical width and height map to the corresponding block and inline axes in vertical page writing mode.
- `pointer-events: auto|none` controls pointer hit testing on text. `none` skips an element's text as a target while allowing descendants to restore targeting with `auto`.
- `user-select: auto|text|none|all` controls text selection. `none` blocks selection without disabling pointer interaction, `text` restores selection inside a disabled ancestor, and `all` selects the owning element's complete text atomically.
- `display: none` suppresses the element, its descendants, and generated content from rendering. `display: block` and `display: flow-root` use block text flow; `display: inline`, `display: inline-block`, and `display: contents` use inline text flow. Multi-keyword flow forms accept order-independent block/inline outer and flow/flow-root inner values. `display: list-item` adds a marker and block text flow; forms such as `inline list-item` place the marker in inline text flow. `<li>` elements use bullets inside unordered lists and ascending decimal numbers inside ordered lists. The predefined CSS Counter Styles Level 3 names are supported for `list-style-type`, `counter()`, and `counters()`, including numeric, alphabetic, fixed, disclosure, localized decimal, kana, Ethiopic, and Japanese, Chinese, and Korean longhand systems. Anonymous `symbols()` styles support cyclic, fixed, symbolic, alphabetic, and numeric systems with string symbols. The CJK longhand styles fall back to `cjk-decimal` outside their supported ranges; disclosure markers use downward and right-pointing triangles. The `list-style` shorthand accepts one marker type. `contents` preserves child flow. Elements remain in the selector tree for structural matching; the renderer models the documented text-flow boxes but does not implement the full CSS formatting-box model.
- Generated content and selection: `::before` and `::after` accept quoted strings and `attr()` expressions through `content`; multiple values can be concatenated. `attr(name, fallback)` emits its token-sequence fallback when the attribute is missing or fails conversion. `type(<string>)`, `type(<number>)`, `type(<integer>)`, `type(<custom-ident>)`, and simple finite `<percentage>`, `<length>`, `<length-percentage>`, `<angle>`, `<time>`, `<frequency>`, and `<resolution>` tokens convert attribute text to those values. Supported style declarations also accept string, integer, number, percentage, length, length-percentage, angle, color, and custom-ident `attr()` values, including typed fallbacks. `calc()`, `min()`, `max()`, and `clamp()` expressions are evaluated for typed integer, number, percentage, length, length-percentage, and angle attribute values. String attributes are substituted as CSS string tokens. `env(safe-area-inset-*)` and `env(safe-area-max-inset-*)` resolve to `0px` on the desktop host; unknown environment names use their fallback if present. Generated text inherits the originating element's style and can override supported text properties. Global and element-scoped `::selection` rules support `background-color` and `color`, including alpha.
- `::first-line` supports `color`, `opacity` (number or percentage, clamped to 0–1), `background-color` and the color-only `background` shorthand, `box-shadow` with rounded corners, `outline` with signed `outline-offset`, physical and logical border properties for width, style, and color, plus supported `border-image` values, `text-decoration-line` values `underline`, `overline`, and `line-through`, font family, size, weight, style, stretch, kerning, supported variants/features, `text-rendering` for glyph shaping, letter spacing, inherited and overridden word spacing, text shadow, text emphasis, and the optional `left|right` side in `text-emphasis-position` in vertical writing, `text-orientation` for glyph orientation, `text-transform` on the first formatted line of a block, `line-height` on the first line box, and `vertical-align` using `baseline`, `sub`, `super`, `middle`, `text-top`, `text-bottom`, `top`, `bottom`, signed lengths, or percentages of line height. `middle` uses the parent x-height, `text-top` compares cap-height metrics, and `text-bottom` uses a 0.2em descent estimate; `top` and `bottom` align the pseudo line box within the parent line-height. Opacity scales alpha on supported pseudo-element paints. Text transformation and word spacing affect wrapping, and the pseudo-element line-height affects the first line box; other typography changes glyph rendering while wrapping and line metrics still come from the base text layout. `::first-letter` inherits supported inherited styles from `::first-line` and selects the first Unicode letter, number, or symbol with its associated preceding punctuation and following punctuation; intervening Unicode space separators are included, except ideographic space. This selected text can span adjacent text runs. `text-transform` changes the selected letter while preserving the punctuation. It supports the same color and decoration properties, including opacity and the color-only `background` shorthand, plus font family, size, weight, style, stretch, kerning, variants, feature settings, `text-rendering` for glyph shaping, line-height, letter-spacing, text-shadow, text-emphasis, and the optional `left|right` side in `text-emphasis-position` in vertical writing, `text-orientation` for glyph orientation, and `vertical-align` with the same supported values. Physical and logical margin and padding properties adjust the initial letter's inline spacing; block padding expands its painted background and border area. Physical and logical border shorthands, side shorthands, and side longhands for width, style, and color paint around the initial glyph; `border-radius` rounds its border corners. `box-shadow` paints outer and inset shadows around the initial letter's inline box. `outline`, `outline-width`, `outline-style`, `outline-color`, and signed `outline-offset` paint an independent outline around the initial letter. Pseudo-element decorations honor the supported `text-decoration-style`, `text-decoration-color`, `text-decoration-thickness`, `text-decoration-skip-ink`, and `text-underline-offset` values; pseudo-elements also accept every other style property implemented by the renderer that is valid on them.
- `::first-letter` also accepts the supported `border-image` source, slice, repeat, width, and outset values, including the shorthand, and paints them around the initial glyph.
- `hyphens: manual` displays a hyphen when a line wraps at U+00AD SOFT HYPHEN; the character stays invisible when the word does not break there. `hyphens: none` disables this discretionary break. `hyphens: auto` adds dictionary break points for recognized `lang` values using embedded Knuth–Liang dictionaries; explicit soft hyphens take priority. A language must be specified on the element or an ancestor for automatic hyphenation. Unsupported or missing languages do not add dictionary break points.

`font-size` in `px`, `em`, `rem`, `lh`, `ex`, `ch`, `ic`, `cap`, viewport units (`vw`, `vh`, `vi`, `vb`, `vmin`, `vmax` and all `sv*`, `lv*`, and `dv*` variants), `%` relative to the inherited size, and absolute units (`cm`, `mm`, `Q`, `in`, `pt`, `pc`), `font-weight` (`normal`, `bold`, `bolder`, `lighter`, or a numeric value from 1 to 1000), `font-style` (`normal`, `italic`, or `oblique` with an values, `line-height` as a multiplier, percentage, `em`, `rem`, `lh`, `ex`, `ch`, `ic`, `cap`, viewport units, or absolute length, `letter-spacing` in `px`, `em`, `lh`, `ex`, `ch`, `ic`, `cap`, or - Text spacing and emphasis: `word-spacing` supports `normal`, signed lengths, and percentages of the font size. `text-emphasis` and `text-emphasis-style` support `none`, single-grapheme strings, and filled/open `dot`, `circle`, `double-circle`, `triangle`, and `sesame` marks. `text-emphasis-color` accepts supported CSS colors and `currentColor`; `text-emphasis-position` supports `over` and `under` for horizontal text and positions marks on the requested `left`/`right` side in vertical flow. Wide-gamut values are perceptually gamut-mapped to sRGB for native rendering.
- `@color-profile` parses local ICC profile declarations and loads valid profiles relative to the declaring stylesheet within the configured resource root. The native renderer accepts loaded profiles through `WindowConfig.color_profiles` and resolves absolute `color()`, relative `color(from ...)`, and custom `color-mix()` spaces in color-valued styles. Little CMS converts ICC grayscale, RGB, CMYK, and multichannel device profiles with up to 15 components; non-device Lab/XYZ and other non-MCH signatures are not currently supported as custom profiles.
- System color keywords include the CSS Color system palette and deprecated aliases. `color-scheme` accepts `normal`, ordered `light`/`dark` and unsupported custom scheme names, plus a trailing `only`; the property inherits, and the first scheme CTML supports selects the palette for system colors in that element's declarations. With no OS preference input, `normal` and unsupported-only lists use the light palette. CTML does not read OS colors or forced-colors mode and has no native form controls for `accent-color`.
- Small/petite caps are synthesized with uppercase glyphs at a reduced size; unicase, titling caps, subscript, and superscript use the selected font's OpenType features. A font without a requested OpenType feature may render the text without that glyph variant.
- Cursor values include the standard `auto`, `default`, `context-menu`, `help`, `pointer`, `progress`, `wait`, `cell`, `crosshair`, `text`, `vertical-text`, `alias`, `copy`, `move`, `no-drop`, `not-allowed`, `grab`, `grabbing`, resize, scroll, and zoom keywords, plus the backend extensions `all-resize` and `dnd-ask`. The OS draws the native cursor icon.
- The cascade follows `!important` priority, selector specificity, and source order. A CTML element may use a `style` attribute for inline declarations; normal inline declarations outrank stylesheet declarations, stylesheet `!important` declarations outrank normal inline declarations, and inline `!important` declarations outrank author stylesheet declarations of equal importance. Text properties inherit through child elements.
- `:focus` and `:focus-within` update when the user clicks text inside a link with `href` or an element with a numeric `tabindex`. Tab and Shift+Tab move focus through links and elements with non-negative numeric `tabindex`; keyboard focus matches `:focus-visible`, while pointer focus does not. CTML has no native form controls, so form-state pseudo-classes are not supported.
- Supported properties accept the CSS-wide keywords `inherit`, `initial`, `unset`, `revert`, and `revert-layer`. `revert` resets a supported declaration to the initial user-agent value modeled by CTML; `revert-layer` rolls back declarations in the current named layer.
- The `all` shorthand accepts those CSS-wide keywords and applies them to every CSS property supported by the renderer.
- Custom properties beginning with `--` inherit with case-sensitive names. `var()` substitutes them in supported property values, including nested fallbacks; cyclic custom properties become invalid and can use a fallback when referenced.
- Text wraps to the available page width. Common block elements start a new line.
- Text can be selected by dragging the left mouse button; double-clicking selects a word.

## Not implemented

For a broader implementation checklist covering CSS feature areas, see the [CSS feature checklist](css-roadmap.md).

Malformed declarations and selector rules are skipped without a warning, and parsing continues with later declarations and rules. Unknown at-rules are skipped. Unknown property names are retained by the stylesheet parser; properties the renderer does not support are ignored without a warning. Unsupported selectors are also ignored without a warning. Malformed layer declarations and unterminated comments fail the build with a file, line, and column diagnostic.

### Selectors and cascade

- Form-state pseudo-classes such as `:disabled`, `:checked`, and `:placeholder-shown`; CTML does not currently define native form controls.
- Selector namespaces. CTML tag names do not accept namespace prefixes and elements do not carry namespace URIs. CSS escaped identifiers are supported for the documented selector forms.
- Shadow-tree and part selectors; CTML does not currently define component shadow trees or parts.
- `:dir(auto)` first-strong character detection; `:dir()` currently uses explicit inherited `dir="ltr|rtl"` values and defaults to `ltr`.
- `:visited`, range state, and `:target`; CTML currently has no link history, range controls, or document navigation target. `:focus`, `:focus-within`, and keyboard-driven `:focus-visible` are supported for the documented focusable elements.
- The `::placeholder` pseudo-element; CTML does not currently define native form controls.
- Pseudo-elements do not support properties the renderer has not implemented for their corresponding element types.

### Layout and sizing

- Formatting boxes beyond the supported text-flow, list-item, run-in, and basic flex forms; Grid, tables, and ruby layout are not implemented.
- Reversed ordered lists, explicit list-item values, and author-defined `@counter-style` rules. The predefined marker systems and `symbols()` forms listed in the supported subset are implemented.
- Full inline and replaced-element box sizing, and general positioned CSS boxes. Supported block dimensions, padding, margins, borders, and gaps affect text flow and paint, but CTML does not build a general browser-style box tree.
- Flex item sizing, wrapping, row cross-axis alignment, `space-evenly`, and wrapped cross-axis gaps; Grid, floats, and positioning (`position`, `top`, `right`, `bottom`, and `left`). Flex direct-item `order` and column `align-self`, row/row-reverse/column/column-reverse flow, block-row main-axis `justify-content` and column cross-axis `align-items` for start, center, and end, `space-between` and `space-around` on block rows, and fixed-length and percentage main-axis gaps with viewport-derived or explicit fixed sizes are supported.
- Scroll snapping and other scroll behaviors beyond the documented clipping, scrolling, and scrollbar support.
- Nested orthogonal text flow is not fully independent: nested vertical blocks compose under a horizontal page root, but nested orthogonal blocks under a vertical page root and additional writing-mode-aware logical layout remain limited.

### Painting and colors

- Background shorthand values outside the documented layer syntax and supported image formats; the shorthand supports comma-separated image/gradient/`none` layers and a color on the final layer.
- Border-image sources other than embedded PNG/JPEG `data:` URLs and rounded border-image corners.
- Filters, backdrop filters, masks, clipping paths, mask compositing, transforms, transform origin/box, 2D/3D transforms, and perspective.
- Image sizing and positioning for replaced content, including `object-fit` and `object-position`.
- Custom ICC profile signatures outside the supported grayscale, RGB, CMYK, and multichannel device spaces; non-device Lab/XYZ profile signatures are not supported.
- OS forced-color palettes and OS preferred-color-scheme negotiation. The `color-scheme` property and fixed light/dark system-color palettes are supported, but CTML does not read those OS preferences.

### Interaction and responsive rules

- `caret-color` and `accent-color`; CTML has no native caret or form controls.
- Custom cursor images (`cursor: url(...)`).
- Media and container queries, `@supports`, and other conditional rules.
- Transitions, keyframe animations, scroll-driven and view-driven animations, and view transitions.

This list describes the current native renderer and will change as CTML's styling and layout support expands.

## Testing CSS support

The [CSS test matrix](css-test-matrix.md) maps each currently supported property, value family, selector, and cascade behavior to its unit and Chromium parity tests.

Run the renderer style resolver tests with:

```sh
cargo test --offline -p ctml-renderer --lib css_style
```

The tests cover numeric font weights, oblique font style, font stretch, small-cap variants, decoration colors, and style cascade behavior. The `ctml-css` tests cover named and alpha colors, `rgb()`/`rgba()`, `hsl()`/`hsla()`, selectors, and malformed color values. The `examples/native-app` demo also exercises supported color and font values visually.

To open the visual demo, run:

```sh
cargo run --offline -p ctml-native-demo
```

The CTML/Chromium screenshot parity suite runs as separate tests for the cases under `crates/ctml-renderer/tests/fixtures/parity/`. Each case has its own CTML, HTML, and CSS files and compares its own screenshots. It uses Chromium from `PATH` or `CHROME_BIN`, then looks for the Chromium Headless Shell in `target/css-parity/chromium-cache/`. It downloads the headless shell only when neither source has a usable executable, and reuses that cached executable on later runs. The downloader is a development-only dependency. Screenshots and red pixel-difference images are saved under `target/css-parity/<case>/`. Exact parity cases fail on any RGB pixel difference. Other cases allow up to 0.05% of pixels above channel tolerance 16, with documented per-case limits for attribute selectors, font-stretch, font-variant-shorthand, line-height-normal, and text-decoration-style in the [test matrix](css-test-matrix.md). To select a Chromium executable explicitly, set `CTML_CSS_PARITY_BROWSER` to its path.

Run the parity test by itself, with a single test thread, using:

```sh
cargo test -p ctml-renderer --lib page::tests::parity -- --test-threads=1 --nocapture
```

The repository's Cargo configuration runs tests serially and shows test output by default. The parity test prints its progress while it parses fixtures, renders CTML, finds or downloads Chromium, captures HTML, and compares pixels. To run only that test, use:

```sh
cargo test -p ctml-renderer --lib page::tests::parity
```

The first run needs network access only if Chromium is not already installed or cached. The downloaded browser is reused by later runs. The parity test requires Chromium to start and capture a screenshot. If a Linux container's seccomp profile blocks a syscall Chromium needs at startup, run the test on the host or allow `shutdown()` in the container profile; the test reports this restriction and fails rather than skipping pixel comparison.
